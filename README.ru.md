# Hephaestus (Ἥφαιστος) — Мультиагентная LLM Arena

Веб-приложение для многомодельного чата, настраиваемых DAG-пайплайнов ("Arena") и **симуляции событий** на базе OpenRouter + **локальных моделей Ollama**.

## Возможности

- **Многомодельный чат**: отправь один промпт нескольким моделям и сравни результаты.
- **Arena-пайплайны**: строй направленный ациклический граф (DAG) из узлов и запускай его.
- **Мультиагентная система**: специализированные агенты (классификатор, аналитик, исследователь, синтезатор, суммаризатор) с предустановленными пресетами.
- **Симуляция событий**: моделирование политических, экономических, военных и технологических событий с кросс-доменным анализом.
- **Локальные модели Olla,ma**: запускай бесплатные локальные модели (Llama, Phi, Qwen) — 100% приватно, без затрат на API.
- **Оптимизация токенов**: контекстное сжатие, RAG, умное чтение файлов — экономия до 80% токенов.
- **Аналитика**: отслеживай использование токенов, оценочную стоимость и Waterfall/Gantt диаграммы.
- **AI File Editing**: ИИ может создавать, редактировать и удалять файлы через чат и пайплайны.
- **Smart Fallback Chain**: автоматический fallback на резервные модели при timeout/error.
- **RAG Knowledge Base**: BM25-поиск по индексированным файлам проекта с включением соседних чанков.
- **Telegram Бот**: взаимодействуй с ИИ через Telegram — текст, фото, документы, голосовые.
- **Конструктор агентов**: визуально строй мультиагентные пайплайны (в стиле OpenClaw).
- **Система навыков (Skills)**: создавай переиспользуемые навыки (формат SKILL.md), которые агенты могут динамически загружать и использовать.

## Установка и запуск

1. Установи зависимости:

   ```bash
   pnpm install
   ```

2. Создай `.env` в корне проекта:

   ```dotenv
   OPENROUTER_API_KEY=YOUR_KEY_HERE
   OLLAMA_BASE_URL=http://localhost:11434  # опционально, по умолчанию
   ```

3. (Опционально) Установи Ollama и загрузи локальные модели:

   ```bash
   curl -fsSL https://ollama.com/install | sh
   ollama pull llama3.1:8b      # Аналитик (~4.7GB)
   ollama pull phi4:latest      # Классификатор/Суммаризатор (~3GB)
   ollama pull qwen2.5:14b      # Исследователь (~9GB)
   ollama pull llama3.1:70b     # Синтезатор (~43GB)
   ```

4. Запусти dev-сервер:

   ```bash
   pnpm dev
   ```

5. Открой: http://localhost:3000

|----------|------|---------------------|------------|-----------|
| **Classifier** | Категоризация входных данных (политика/экономика/военное/риск) | Gemma 2B (бесплатно) | 20-50 | $0 |
| **Analyst** | Структурированный анализ с выводами и рисками | Llama 3.1 8B (бесплатно) | 800 | $0 |
| **Researcher** | Глубокий анализ с историческим контекстом | Qwen 235B | 2000 | Низкая |
| **Synthesizer** | Объединение мульти-агентного анализа в финальный отчёт | Claude Opus | 3000 | Премиум |
| **Summarizer** | Сжатие до ключевых тезисов | Gemma 9B (бесплатно) | 300 | $0 |

### Агентные пресеты

19 преднастроенных пресетов в `lib/agent-config.ts`:

- **4 Классификатора**: политический, экономический, военный, уровень риска
- **2 Роутера**: по домену, по срочности
- **4 Аналитика**: политический, экономический, военный, технологический
- **2 Исследователя**: политический, экономический
- **2 Синтезатора**: стратегический (Claude Opus), краткий (Claude Sonnet)
- **1 Валидатор**: факт-чекер
- **1 Суммаризатор**: executive summary
- **5 Ollama локальных**: бесплатные локальные модели для всех ролей

## Arena: пайплайны (DAG)

Пайплайн — это DAG, определяемый:

- Узлы: `ArenaNode[]`
- Рёбра: `ArenaEdge[]`

Выполнение производится через `lib/executor.ts::executePipeline()`.

### Типы узлов

Тип узла — `ArenaNode.type`:

- `prompt` — производит текстовый вывод через шаблон. Поддерживает `{{input}}`, `{{context}}`, `{{global}}`.
- `model` — вызывает `/api/chat` для стриминга ответа LLM.
- `validator` — валидация/саммари/оценка upstream-выходов.
- `aggregator` — объединение upstream-выходов в единый финальный ответ.
- `search` — веб-поиск через DuckDuckGo.
- `file` — чтение файлов с **Smart Read** для больших файлов.
- `router` — LLM-классификатор с активацией одного из исходящих путей.
- `code` — создание/редактирование/удаление файлов через `/api/files/edit`.
- **`classifier`** — быстрая категоризация (20-50 токенов, строгий вывод).
- **`analyst`** — структурированный анализ с выводами и рекомендациями.
- **`researcher`** — глубокий анализ с историческим контекстом и сценариями.
- **`synthesizer`** — объединение мульти-агентного анализа в стратегический отчёт.
- **`summarizer`** — сжатие до ключевых тезисов.

### Топология и параллелизм

- Executor запускает узлы слоями на основе in-degree (топологическая прогрессия).
- Узлы одного слоя могут выполняться параллельно.
- Параллельные узлы слегка разносятся во времени (`idx * 300ms`) для снижения rate-limits.

### Таймауты и ретраи

- У каждого узла жёсткий таймаут: **5 минут**.
- Вызовы LLM используют retry-обёртку, которая ретраит при `429` с экспоненциальным backoff.

### Холостой запуск (Dry run)

UI Arena предлагает **Dry Run (Preview Prompts)** — нет внешних API-вызовов, полезно для инспекции точных промптов.

## Стратегии оптимизации токенов

### 1. Рациональный выбор моделей

- **Классификаторы** → микро-модели (Gemma 2B), maxTokens: 20-50
- **Аналитики** → бесплатные модели (Llama 8B), maxTokens: 800
- **Синтезаторы** → одна дорогая модель (Claude/GPT-4), maxTokens: 3000
- **Экономия: 60-70%**

### 2. Контекстное сжатие

- Встроенное `contextCompression` в узлах
- Сжимает входной контекст перед отправкой в модель
- Порог: 1000 токенов, цель: 50% сжатия
- **Экономия: 30-50%** на промптах

### 3. RAG вместо полного контекста

- BM25 поиск релевантных чанков
- **Включение соседних чанков** для лучшего контекста
- Default topK: 5 (было 3)
- **Экономия: 90%** на больших документах

### 4. Умное чтение файлов (Smart File Reader)

- AI выбирает только релевантные строки из файлов
- 500 строк из 10,000+ строчных файлов
- **Экономия: 95%** на чтении файлов

## База знаний (Global Knowledge)

Пайплайн может инжектить содержимое локальных файлов в контекст AI-узлов.

Как это работает:

1. Пометь любой `file`-узел как **Global** (или добавь файлы вручную через UI Knowledge Base).
2. Executor обнаруживает уникальные KB-пути (глобальные file-узлы + ручной список).
3. Для каждого пути executor загружает контент через `/api/files` и конкатенирует его.
4. Для AI-узлов:
   - Если промпт узла **не** содержит `{{global}}`, executor автоматически добавляет KB-контент в начало.

## Система навыков (Skills, в стиле OpenClaw)

Создавай переиспользуемые навыки, которые агенты могут динамически загружать и использовать во время разговора.

### Создание навыков

Навыки хранятся в директории `./skills` со следующей структурой:

```
skills/
  my-skill/
    SKILL.md
```

### Формат SKILL.md

Каждый навык использует YAML frontmatter + markdown тело:

```markdown
---
name: Мой навык
description: Что делает этот навык
category: optional-category
---

## Что это за навык?

Подробное описание назначения и возможностей навыка.

## Как использовать

Пошаговые инструкции по использованию навыка.

## Примеры

\`\`\`
Пример использования
\`\`\`
```

### Использование навыков в чате

Навыки автоматически обнаруживаются и предоставляются ИИ как инструменты. Агент может вызвать:

```
skill(skill_name="my-skill")
```

Это загружает содержимое навыка и предоставляет его агенту for use in the conversation.

### UI управления навыками

Доступ к Skill Manager через Agent Constructor для:
- Создания новых навыков с визуальным редактором
- Просмотра и управления существующими навыками
- Организации навыков по категориям

## AI File Editing & Tools

ИИ в чате может использовать инструменты:

- `list_files` — список файлов проекта.
- `read_file` — чтение файла.
- `write_file` — создание/перезапись файла.
- `edit_file` — редактирование (str_replace).
- `delete_file` — удаление файла.
- `web_search` — веб-поиск.
- `skill` — загрузить и использовать навык by name.

### Multi-step Tool Chains

ИИ может выполнять цепочки: `list_files → delete_file(file1) → write_file(new)` — всё в одном запросе.

## Smart Fallback Chain

Model узлы поддерживают цепочку fallback:

- `fallbackModels`: резервные модели.
- `fallbackTimeoutMs`: таймаут перед fallback (по умолчанию: 5000ms).
- `fallbackMode`: `'timeout'` (по времени) или `'on_error'` (только при ошибке).

## Context Compression

Автоматическое сжатие длинных контекстов в model узлах:

- `enabled`: включить.
- `thresholdTokens`: порог (по умолчанию: 1000).
- `targetRatio`: целевое сжатие 0.0-1.0.

## Аналитика и экспорт

- **Waterfall/Gantt**: визуализация выполнения пайплайна.
- **Экспорт**: PDF и CSV отчёты.
- **Метрики**: prompt/completion токены, стоимость, latency.

## Решение проблем

### `OPENROUTER_API_KEY is missing`

- Убедись, что `.env` существует в корне проекта и содержит `OPENROUTER_API_KEY`.
- Перезапусти dev-сервер после редактирования `.env`.

### Ollama: Connection Refused

- Убедись, что Ollama запущен: `ollama list`
- Проверь `OLLAMA_BASE_URL` в `.env` (по умолчанию: `http://localhost:11434`)

### Rate limits (429)

- Executor ретраит с backoff, но тяжёлые параллельные пайплайны всё равно могут упираться в лимиты.
- Уменьши количество параллельных узлов или упрости граф.

### Ошибки веб-поиска

- DuckDuckGo Lite иногда блокирует/меняет разметку.
- Если поиск возвращает `[Search failed: ...]`, отключи `webSearch` для модели.

## Замечания по безопасности (важно)

- **Никогда не комить `.env`**. Твой ключ OpenRouter должен быть секретом.
- Эндпоинты `/api/files` и `/api/files/edit` могут читать и изменять **любой файл внутри корня проекта**.
- Это нормально для локальной разработки, но **небезопасно для публичных деплоев**.
- Для продакшена: добавь auth + allowlist путей.

## Идеи для развития

- Auth + per-user storage
- Жёсткий allowlist для чтения файлов (KB)
