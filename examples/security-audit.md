# Аудит безопасности в Кузнице

Пайплайн: [`security-audit.pipeline.json`](security-audit.pipeline.json).

```
Цель → Разведка ─┬→ $ repo-janitor ────────┐
                 ├→ $ npm audit ───────────┼→ Отсев (список кандидатов, JSON)
                 └→ Карта атаки ───────────┘        │
                                                    ▼
                         Охотник — «Для каждого»: каждый кандидат отдельно, по 3 одновременно
                                                    ▼
                         Перепроверка → Проверка достоверности ─┬→ Отчёт → audit/report.md
                                                                └→ Доработчик сканера → Тесты сканера ($ vitest, по коду выхода)
```

| Блок | Тип | Что делает |
|---|---|---|
| Разведка | агент | Языки, точки входа, конфиги, часто меняемые файлы → `audit/recon.md` |
| repo-janitor | команда | `npx repo-janitor scan` — без модели, секунды → `audit/repo-janitor.json` |
| Уязвимые зависимости | команда | `npm audit` → `audit/npm-audit.json` (нет npm-проекта — блок просто сообщит об этом) |
| Карта атаки | агент | Пары «откуда приходят данные → где опасны» → `audit/attack-map.md` |
| Отсев | агент | Убирает дубли и шум (шум — в `audit/triage-noise.md`), до 30 кандидатов → `audit/candidates.json` |
| Охотник | для каждого | Каждого кандидата проверяет отдельный вызов модели: путь данных, тест в `audit/poc/`, похожие места по всему коду. Opus 4.8 · high, запасная — «Умная» |
| Перепроверка | агент | Независимо проверяет подтверждённое, собирает ложные срабатывания сканера → `audit/verified.md` |
| Проверка достоверности | проверка моделью | Возвращает на доработку, если у находок нет пути:строки и пути данных |
| Отчёт | агент | Отчёт для мейнтейнеров → `audit/report.md` |
| Доработчик сканера | агент | В клоне repo-janitor (`@tools/repos/repo-janitor`), в ветке `audit/<дата>`: до двух узких правок правил + регрессионные тесты, коммит без пуша |
| Тесты сканера | проверка командой | `npx vitest run test/scanners` — красные тесты возвращают доработчику конец вывода, до 2 раз |

Команды в блоках работают и в Windows (`cmd.exe`), и в Linux/macOS.

## Как запустить

1. **Рабочая папка** — проверяемый репозиторий. **Терминал** — «Полный доступ», лимит на команду — 900 с (первый `npx` скачивает repo-janitor).
2. **Модели.** Охотник — `anthropic/claude-opus-4.8 · high`: при «Подписке в приоритете» это Opus 4.8 по подписке Claude; не сработала — через OpenRouter; недоступно — роль «Умная». Остальные — роли «Основная» и «Умная». Меняются в блоке или в Настройках → Роли моделей.
3. **Кузница → Импорт → Пайплайн из JSON-файла** → `security-audit.pipeline.json`.
4. **Вход** — цель и фокус, например: `Проверь API. Особое внимание — доступ к чужим данным. Категория для доработки сканера: insecure-code`.
5. **Запустить** (в первый раз — «Пошагово»).

Результаты — в `audit/` рабочей папки; доработка сканера — ветка в `@tools/repos/repo-janitor` (`git log audit/…`, `git diff main`).

## Новые блоки Кузницы

- **Команда** — запускает команду без модели. Вывод — выход блока. «Ошибка — не ошибка» для сканеров, которые сообщают о находках кодом выхода.
- **Для каждого** — делит вход на элементы (строки, разделы Markdown, массив JSON) и обрабатывает каждый отдельным вызовом агента, по N одновременно. В промпте — `{{item}}` и `{{index}}`. Ошибка одного элемента не роняет блок.
- **Проверка командой** — в блоке «Проверка» режим «Командой (код выхода)»: тесты, сборка, повторный скан. Не прошло — агенты на входе получают конец вывода и дорабатывают.
- **Своя копия проекта** — переключатель у агента: он правит копию, а не оригинал; команды и проверки после него выполняются в его копии. После запуска в блоке — список изменений, diff и «Применить к проекту».
