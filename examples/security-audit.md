# Аудит безопасности в Кузнице

Пайплайн: [`security-audit.pipeline.json`](security-audit.pipeline.json).

```
Цель аудита → Разведка ─┬→ Сканеры ─────┐
                        └→ Карта атаки ─┴→ Отсев ─┬→ Инъекции и выполнение кода ─┐
                                                  ├→ Доступ и аутентификация ────┼→ Перепроверка → Проверка достоверности ─┬→ Отчёт → audit/report.md
                                                  └→ Секреты, конфигурация, зависимости ┘                                 └→ Предложения для сканера
```

| Блок | Что делает | Модель |
|---|---|---|
| Разведка | Клонирует цель (если дана ссылка), находит языки, точки входа, конфиги, часто меняемые файлы → `audit/recon.md` | Основная |
| Сканеры | repo-janitor, semgrep, аудит зависимостей, поиск секретов; ставит их один раз в `@tools` → `audit/scan-*.json`, `audit/scan-summary.md` | Основная |
| Карта атаки | Пары «откуда приходят данные → где они опасны» с путями и строками → `audit/attack-map.md` | Основная |
| Отсев | Убирает дубли и шум, раскладывает кандидатов по трём областям → `audit/candidates.md` | Основная |
| Три охотника (параллельно) | Проверяют кандидатов своей области по коду, пишут тесты в `audit/poc/`, ищут такие же места по всему коду, выписывают ложные срабатывания сканеров → `audit/findings-*.md` | Opus 4.8 · high, запасная — Умная |
| Перепроверка | Независимо проверяет каждую подтверждённую находку, запускает тесты → `audit/verified.md` | Умная |
| Проверка достоверности | Отправляет перепроверку на доработку, если у находок нет пути:строки и пути данных | Умная |
| Отчёт / Предложения для сканера | Отчёт для мейнтейнеров; узкие правила и регрессионные тесты для repo-janitor по пропускам и ложным срабатываниям | Умная |

Все промежуточные результаты лежат в `audit/` рабочей папки — их можно открыть и после запуска.

## Как запустить

1. **Рабочая папка** — тестовый репозиторий (или пустая папка, если цель — ссылка). **Терминал** — «Полный доступ», лимит на команду — 600–1800 с: установка semgrep и сборка repo-janitor в первый раз долгие, потом берутся из `@tools`.
2. **Модели.** Охотники стоят на `anthropic/claude-opus-4.8 · high`: при включённой «Подписке в приоритете» это Opus 4.8 по подписке Claude, если подписка не сработала — через OpenRouter, если и он недоступен — роль «Умная». Остальные блоки — роли «Основная» и «Умная», их можно сменить в Настройках → Роли моделей или в самом блоке.
3. **Кузница → Импорт → Пайплайн из JSON-файла** → `security-audit.pipeline.json`.
4. **Вход**: путь в рабочей папке, ссылка на репозиторий или пусто (вся рабочая папка). Можно добавить фокус: `https://github.com/owner/app — особенно загрузка файлов и админка`.
5. **Запустить.** Для первого раза включите «Пошагово» — посмотрите результат разведки и сканеров, прежде чем запускать охотников.

Отказы моделей: в системном промпте прямо сказано, что это защитный аудит своего кода и что нужны доказательства (путь данных, пример входа, тест), а не боевые эксплойты. Если модель охотника всё же откажется или упадёт — блок повторит запрос и перейдёт на запасную модель.
